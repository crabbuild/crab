# Local workflows

The `local` feature controls an ordinary Git worktree. It requires absolute
paths to compatible Git and Crab executables. The SDK validates their versions
and capabilities before changing repository state.

```rust
use crab_sdk::local::{Options, Tools};
use crab_sdk::storage::DirectStoreOptions;
use crab_sdk::{Client, OpenOptions};

let tools = Tools::new("/usr/bin/git", "/usr/local/bin/crab")?;
let client = Client::builder()
    .direct_store(DirectStoreOptions::s3_from_env("bucket")?)
    .local(Options::new(tools))
    .build()?;
let configuration = client.configure_local("./checkout").await?;
let repository = client.open(OpenOptions::local("./checkout")).await?;
let local = repository.local()?;
```

Configuration is repository-local. Child processes receive the selected tools
and credentials without changing the application environment, current
directory, or global Git configuration.

## Clone and fetch

`Client::clone_local` publishes its destination only after packs, refs,
shallow state, `FETCH_HEAD`, filters, and checkout succeed. Direct and managed
Crab clones use shared Rust transfer services. `RepositoryLocator::http`
selects native Git smart HTTP.

`local::CloneOptions` controls the branch, depth, and hydration override.
`local::FetchOptions` supports pruning, tags, depth, deepen, and unshallow.
Fetch does not integrate `HEAD`. Linked worktrees share their common object
directory while retaining separate `HEAD` and index state.

Opening a local repository validates durable fetch or integration state without
changing it. The next serialized fetch or pull completes eligible recovery
before starting new work.

## Edit and integrate

`local::Local` provides `status`, `stage`, `commit`, `checkout`,
`pull`, `hydrate`, `dehydrate`, and `prefetch_content`. Pull supports
fast-forward-only, merge, and rebase. Conflicts return an `IntegrationId` and
exact paths for `continue_integration` or `abort_integration`.

The default `local::ExecutionPolicy::Untrusted` disables repository hooks and
unrecognized executable Git drivers. Enable trusted execution only for a
repository whose executable configuration should run:

```rust
use crab_sdk::local::{ExecutionPolicy, Options};

let options = Options::new(tools)
    .with_execution_policy(ExecutionPolicy::Trusted);
let client = Client::builder().local(options).build()?;
```

## Prepared push

```rust
use crab_sdk::local::{PushOptions, PushOutcome};

let prepared = local.prepare_push(PushOptions::current_branch()).await?;
persist(prepared.recovery_token().to_json()?);
match prepared.execute().await? {
    PushOutcome::Committed { readiness, .. } => record(readiness),
    PushOutcome::TransportCommitted { destinations } => record(destinations),
    PushOutcome::Indeterminate { recovery } => persist(recovery.to_json()?),
    PushOutcome::DryRun { .. } => unreachable!(),
    _ => {}
}
```

Direct Crab push uses the shared Rust publication path. Managed and HTTP
worktrees use protected or native Git transport. Every destination is guarded by
the exact remote value observed during preparation.
