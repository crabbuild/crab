# Managed repositories

The `managed` feature resolves logical `crab://` locators through the
installed Crab profile and encrypted token cache. Remote reads receive
read-scoped grants. Local protected push obtains a distinct authorized session.

```rust
use crab_sdk::managed::Options;
use crab_sdk::{Client, OpenOptions, RepositoryLocator};

let client = Client::builder()
    .managed(Options::new(token_cache_directory)?)
    .build()?;
let locator = RepositoryLocator::managed(
    "api.crab.build",
    "organization",
    "repository",
)?;
let repository = client.open(OpenOptions::remote(locator)).await?;
let remote = repository.remote()?;
```

A managed locator uses the same `Client::open` and `Client::clone_local`
paths as other locators. The caller does not receive a third repository type.
Grant refresh, revocation, placement changes, and cache isolation stay inside
the managed authentication owner.

## Repository lifecycle

Administration is client-scoped because list and create do not act on an opened
repository:

```rust
let managed = client.managed().await?;
let page = managed.list("organization", None, 100).await?;
let created = managed
    .create("organization", "models", persisted_idempotency_key)
    .await?;
```

`managed::Managed` provides list, create, rename, archive, and restore as lazy
request builders. Create requires a caller-persisted idempotency key. Rename,
archive, and restore also require the last observed revision and an idempotency
key.

Lifecycle results use the service's canonical URL. Replace stored locators after
a rename instead of constructing a new URL. An in-memory bearer token can serve
remote operations, but it cannot be delegated to local Crab filter processes;
use the encrypted token cache for managed local workflows.
