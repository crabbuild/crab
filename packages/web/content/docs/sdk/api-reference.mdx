# API reference

The SDK exposes one client, one repository facade, and task-specific namespaces.

| Path | Purpose |
| --- | --- |
| crate root | Client construction, repository selection, core identifiers, errors, and shared write policy |
| `remote` | Pinned refs, snapshots, Git reads, content streams, and archives |
| `remote::write` | Streamed commits, atomic ref batches, outcomes, and recovery tokens |
| `local` | Tool policy, local worktree reads, edits, integration, hydration, and push |
| `managed` | Managed service configuration and repository administration |
| `operation` | Lazy requests, cancellation, deadlines, limits, progress, and operation identity |
| `storage` | Direct S3, GCS, Azure, filesystem, and content cache configuration |

## Repository lifecycle

`Client::open(OpenOptions)` opens every existing repository and returns
`Repository`. Use `OpenOptions::remote(locator)` for an object-store or
managed remote. Use `OpenOptions::local(path)` for an existing Git worktree.

`Repository::remote()` returns `remote::Remote`; `Repository::local()`
returns `local::Local`. Both accessors are synchronous and perform no I/O.
Selecting an interface that does not match `Repository::mode()` returns
`ErrorKind::UnsupportedCapability`.

Creation stays explicit:

- `Client::initialize_remote` creates empty direct remote state.
- `Client::clone_local` creates a local worktree and returns `Repository`.
- `Client::configure_local` configures an existing worktree.

## Core values

- `RepositoryLocator::new` validates a direct storage prefix.
- `RepositoryLocator::managed` validates an authority, organization, and repository.
- `RepositoryLocator::http` validates an HTTP(S) source for local workflows.
- `Revision::branch`, `Revision::tag`, and `Revision::commit` avoid ambiguous names.
- `GitPath` stores validated repository-relative bytes.
- `ObjectId` accepts complete SHA-1 object IDs.

## Requests and outcomes

SDK operations return awaitable `operation::Request` values. Apply
`operation::Options` with `with_options`. Remote reads that support ranges and
read limits use `operation::ReadOptions`.

Remote mutations return
`remote::write::MutationOutcome::{Committed, Rejected, Indeterminate}`. Local
push uses `local::PushOutcome`, including dry-run and transport outcomes.
Local pull distinguishes updated, current, conflict, and pending-hydration
states.

Use generated rustdoc for constructor and error details. Public enums are
non-exhaustive, so external matches need a fallback arm.
