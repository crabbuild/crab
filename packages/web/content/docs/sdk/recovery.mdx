# Mutation recovery

Network loss after publication can hide whether refs changed. Crab returns an
indeterminate outcome instead of guessing or replaying the mutation.

## Durable identity

Persist `remote::write::PreparedMutation::recovery_token()` or
`local::PreparedPush::recovery_token()` before execution. Tokens bind the
repository, expected refs, immutable artifacts, and plan identity without
containing credentials.

`remote::write::RecoveryToken::to_json` and
`local::PushRecoveryToken::to_json` produce bounded, versioned documents.
Decode untrusted input with the corresponding `from_json` constructor. Native
remote recovery tokens use version 5 and bind the protocol version into their
request digest. Legacy repository tokens are rejected, including tokens with a
changed version field. Local push tokens use version 4 and bind Git push URLs;
previous local push tokens must be prepared again.

## Reconcile before replay

Use the family-specific client operations:

```rust
let remote_outcome = client.reconcile_remote(remote_token).await?;
let push_outcome = client.reconcile_local_push(push_token).await?;
```

Reconciliation reads durable evidence and never writes or replays. An
unattempted direct remote plan can resume through
`Client::resume_remote(token, scratch)`. An eligible local push can resume
through `Client::resume_local_push(token, scratch)`. A plan with unresolved
attempt evidence is never replayed automatically.

Git HTTP and SSH push tokens have no durable server receipt. Both recovery
operations return an indeterminate outcome without replay, even when current
refs match the requested targets. Execute the original prepared handle for a
fresh Git attempt. Unchanged native capsule pushes validate the current source,
placement and refs and report the already satisfied destinations without writes.
A token cannot grant trusted local execution beyond the client's policy.

An opened remote interface also provides `remote.reconcile(token)`, which
checks that the token belongs to that opened repository.

## Readiness

A committed mutation can return `remote::write::Readiness::Pending` when the
durable ref update succeeded but derived read indexes did not become visible
within the request budget. The commit remains successful. Refresh or retry the
read later; do not republish the mutation.
