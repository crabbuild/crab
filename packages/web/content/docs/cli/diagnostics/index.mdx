# Diagnose and repair a repository

Start with the narrowest command that identifies the failing boundary. Preserve logs and structured output before applying repair, recovery, or destructive maintenance.

## Capture the first useful evidence

Run health and integrity checks without changing repository state:

```bash
crab doctor
crab fsck
crab logs last
```

Keep the first error code and the command that produced it. Repeated retries can replace useful context with secondary failures.

Use JSON when automation or a support bundle needs stable fields:

```bash
crab doctor --json > doctor.json
crab fsck --json > fsck.json
```

## Choose the tool from the failing boundary

| Symptom | First command | Evidence to inspect | Next page |
| --- | --- | --- | --- |
| Credentials, filters, or remote configuration fail | `crab doctor` | Failed check, remediation, resolved provider | [Health checks](/docs/cli/diagnostics/health-check) |
| A pointer cannot hydrate | `crab fsck` | Recipe, shard, xorb, and restore status | [Integrity checks](/docs/cli/diagnostics/integrity-check) |
| A command returns `CRAB-E####` | `crab errors CRAB-E####` | Meaning, cause, and remediation | [Error codes](/docs/cli/diagnostics/error-codes) |
| A ref changed unexpectedly | `crab recover history list` | Retained generations and exact historical roots | [Recovery operations](/docs/cli/diagnostics/recovery-operations) |
| Metadata opens slowly or reports corruption | `crab metadb diagnose` | Database generation and validation result | [Metadata databases](/docs/cli/diagnostics/metadata-database) |
| Archived data blocks hydration | `crab hydrate --restore` | Storage class and restore state | [Hydrate restore](/docs/cli/diagnostics/hydrate-restore) |

## Repair only after classification

`crab fsck --repair` is not a substitute for diagnosis. Review the dry result first, confirm that the command targets the intended repository, and retain its output.

After any repair, rerun the original check and hydrate a representative file from an isolated client. A clean metadata report alone does not prove that remote bytes reconstruct correctly.

Prefer a new clone or an empty cache for this final hydration so local cached
chunks cannot hide a missing remote object.

## Preserve an incident record

Record these artifacts together:

- The first failing command and exit code
- Crab version and operating system from `crab version --json`
- `crab doctor --json` output with secrets excluded
- Integrity or recovery output used to approve the action
- The repair command and its terminal result
- The verification command and a representative hydration result
