## Checking Version Information

Knowing which version of Crab you're running matters for compatibility checks, bug reports, and ensuring you have the latest features. `crab version` gives you the version string, git commit SHA, and build timestamp in one command.

## Usage

```bash
crab version
```

```bash
crab 1.0.15 (<build commit>)
built at <UTC timestamp>
```

## When Version Matters

| Scenario | Why |
|----------|-----|
| Filing a bug report | Maintainers need to know the exact build |
| Compatibility check | Repository version guard may require a minimum version |
| After upgrading | Confirm the new version is active |
| CI pipelines | Log which version ran the job |

## Including in Bug Reports

Pair version info with environment details for a complete picture:

```bash
crab version
crab env
crab doctor
```

Also confirm which executable the shell resolves when multiple installations
may exist:

```bash
command -v crab
crab version --json
```

The semantic version identifies the release. The Git SHA and build timestamp
distinguish an official release binary from a locally rebuilt binary with the
same package version. Keep all three fields in incident evidence.

## Schema Registry

The JSON output includes the schema registry — a list of all supported structured output schemas and their versions. This is useful for automation that needs to know which output formats are available:

```bash
crab version --json
```

```json
{
  "schema": "version",
  "version": "1.0",
  "data": {
    "crab_version": "1.0.15",
    "git_sha": "<build commit>",
    "build_timestamp": "<UTC timestamp>",
    "schemas": {
      "add": "1.0",
      "du": "1.1",
      "hydrate": "1.0",
      "status": "1.0"
    }
  }
}
```

## Check compatibility without guessing

Repository and service compatibility errors should name the required version.
Do not infer compatibility from release dates alone. Compare the installed
version with the explicit minimum, then use `crab upgrade` or the package
manager that owns the installation.

After upgrading, open a new shell if command hashing or environment activation
can retain an older path. Run `command -v crab` and `crab version` again before
rerunning the failed operation. In CI, print version JSON near the start of the
job so later structured output can be interpreted against the schema registry
from the same binary.

## Use the schema registry in automation

The registry reports the output schemas supported by this installed release.
An integration can check for the required schema name and version before
running a command, then reject an incompatible runner with a clear message.
This is safer than parsing human help text or assuming every machine was
updated at the same time.
