# Metadata diagnostics

Capsule v2 stores authenticated catalogs in checkpoints and capsules selected
by `v2/root` and transaction-consistent ref heads. Missing or corrupt authority
fails closed. Metadata commands do not select a legacy database when the root
is absent.

## Identify the failing boundary

```bash
crab metadb diagnose --json
crab doctor --metadb --json
crab metadb diagnose --deep --json
```

Default diagnosis authenticates root/ref state and reports generation, digests,
visible refs/capsules, and checkpoint presence. It does not download stable Git
packs. Doctor adds local cache health. Configuration, authority, storage, and
cache failures return non-zero instead of reporting empty legacy databases or
an absent corrupt cache.

Deep diagnosis checks catalogs, canonical shards and xorbs, visibility, and the
reachable Git closure from one captured view. A final activity probe rejects
results if repository state changed during verification. Retry during a stable
window. These checks do not change remote authority.

## Verify and checkpoint

```bash
crab metadb rebuild --json
```

Rebuild acquires maintenance and GC writer fences, captures authority, and
verifies the complete closure before publishing a checkpoint. Publication uses
an exact root compare-and-swap. Conflicting maintenance fails; concurrent ref
updates remain as an authenticated suffix. Empty repositories and already
covered capsule frontiers need no new checkpoint.

Use this for checkpoint maintenance after source integrity is established.
Missing authoritative metadata, shards, xorbs, or Git content require verified
history, a replica, or a backup. Rebuild cannot restore absent bytes by listing
unrelated objects. The former `--db` selector and `metadb compact` are removed.

## Maintain a team repository

```bash
crab metadb owner --interval 30 --jsonl
crab metadb owner --once
```

One renewable owner lease serializes maintenance. Continuous operation waits
for unchanged root/ref activity for at least one polling interval and five
seconds, then checkpoints eligible frontiers and repacks eligible checkpoints.
`--once` is eager. Quiet polling still captures independent ref heads; request
cost scales with ref count. See [command reference](/docs/cli/reference/crab-metadb)
for thresholds and telemetry.

## Inspect the local cache

```bash
crab metadb cache stats
```

The read-only SQLite inspection reports chunk and installed-shard counts,
GC generation, and the main database-file size. It does not load all rows,
create a missing cache, migrate schema, or replace corrupt bytes. WAL and
shared-memory sidecars are excluded from the reported size.

Stop Crab processes using this bucket before `crab metadb cache clear`. The
current clear command removes the database file; the next operation starts
cold. Remote content is unchanged.

## Choose recovery from the evidence

| Finding | Next action |
| --- | --- |
| Root missing or corrupt | Verify repository/provider configuration; restore authenticated authority from retained history, replica, or backup |
| Deep diagnosis reports missing content | Restore the exact authenticated object, then repeat deep diagnosis and an independent hydration |
| Activity changed during diagnosis | Retry against a stable repository window |
| Cache unreadable or schema invalid | Preserve the failing path and error; stop users of that cache before removal and cold reopening |
| Healthy source, checkpoint maintenance needed | Run rebuild or the owner, then repeat diagnosis |

Retain JSON output, first error, binary version, and the final independent
hydration result with the incident record.
