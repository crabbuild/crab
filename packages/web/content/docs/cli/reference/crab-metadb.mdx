# crab metadb

Inspect and maintain the Capsule v2 authority selected by `v2/root` and its
transaction-consistent ref heads. Missing or corrupt authority returns an error.

## Synopsis

```bash
crab metadb diagnose [--deep] [--json]
crab metadb rebuild [--json]
crab metadb owner [--once] [--interval SECONDS] [--jsonl]
crab metadb cache stats
crab metadb cache clear
```

## Subcommands

| Command | Purpose |
| --- | --- |
| `diagnose` | Authenticate root/ref state; add `--deep` to verify the complete reachable metadata and content closure |
| `rebuild` | Verify complete content and publish a checkpoint from the captured view |
| `owner` | Continuously checkpoint and repack eligible Capsule state |
| `cache stats` | Inspect SQLite counts and database-file size through a read-only connection |
| `cache clear` | Remove the local SQLite database file after processes using it have stopped |

The `--db` selector and `metadb compact` are removed. Capsule catalogs are one
authenticated unit. `crab optimize indexes diagnose` and `rebuild` use the same
implementations. [`crab compact`](/docs/cli/reference/crab-compact) consolidates
remote shards separately.

## Diagnosis and rebuild

```bash
crab metadb diagnose --deep --json
crab doctor --metadb --json
crab metadb rebuild --json
```

Default diagnosis reads root/ref authority without stable pack bodies. Deep
diagnosis validates catalogs, shards, xorbs, visibility, and the reachable Git
closure, then rejects a result if repository activity changed during the check.
Doctor reports Capsule authority and local cache health; unreadable or corrupt
caches fail instead of appearing absent.

Rebuild acquires maintenance and GC writer fences before capturing authority.
It validates the complete closure before no-op success or checkpoint publication.
Root compare-and-swap rejects conflicting maintenance; concurrent ref updates
remain as an authenticated suffix. An empty repository or already covered
frontier needs no checkpoint. JSON reports publication and verified counts;
legacy index-write counters remain zero. Rebuild cannot restore missing source
bytes or invent catalog entries from unrelated bucket objects.

## Continuous maintenance

```bash
crab metadb owner --interval 30 --jsonl
crab metadb owner --once
```

Run one owner under a process supervisor. It requires valid Capsule authority,
holds a renewable exclusive owner lease, and drains cooperative cancellation
before release. A second owner fails lease acquisition.

The continuous owner waits for unchanged root/ref activity for at least one
polling interval and five seconds. It checkpoints a frontier of at least 32
capsules and revisits multi-pack checkpoints for physical repacking. `--once`
eagerly maintains a nonempty Git frontier. Stable completed state is reused for
up to ten minutes before full maintenance revalidation; quiet polls still read
independently mutable ref heads, so cost scales with ref count.

JSONL identifies the action, reason, eligibility, generation, and whether pack
inventory was loaded. Zero pack counts with `inventory_loaded: false` do not
mean the repository is empty. Legacy locator and graph work counters stay zero.

## Local cache

Stats never creates, migrates, or repairs the cache, and does not materialize
all chunk rows. It reports the main database-file size, excluding WAL and
shared-memory sidecars. Stop Crab processes using the bucket before `cache
clear`: the current command unlinks the SQLite file and requires a cold reopen.
It does not change remote content.

For recovery guidance, see [Metadata diagnostics](/docs/cli/diagnostics/metadata-database).
