# crab gc

Remove unreachable objects from storage.

## Synopsis

```bash
crab gc [OPTIONS]
```

## Description

`crab gc` identifies and removes repository objects that are not referenced by
the current repository state, ref journal, workflow artifact catalog, or any
immutable recovery root. It respects a grace period to avoid deleting objects
that may be in use by concurrent operations.

Historical roots used by `crab recover history` are retained without a time or
count limit by default. Objects referenced by those roots are therefore not GC
candidates, even when they are absent from current branches and tags. Use
`crab recover history prune --keep-last N` to preview an explicit retention
boundary, apply it with `--apply`, and then rerun GC.

Writers take shared renewable fences through publication. GC performs root
walking and namespace listing online, then takes short exclusive fences for
root reconciliation, each 512-object delete batch, and each file-index
partition. A writer admitted between batches advances the fence epoch and
causes the run to fail closed before another delete. History pruning and
restoration use the same admission boundary. Bucket destruction also requires
complete registry and coordinator safety proof.

Bucket GC streams current shard roots from per-repository, four-hex CAS
partitions and reads retained historical roots for registered repositories. It
validates bounded, segmented shard closures without referenced-shard body GETs
and adaptively lists the complete global shard and xorb namespaces. Small
namespaces use one recursive stream per kind; larger namespaces switch to
concurrent populated hash partitions after a bounded provider-aware probe. The
crossover waits until recursive pagination reaches the cost of the complete
256-way fan-out, bounding restart overhead to about 2x at the threshold. It
persists partitioned reachability marks and candidate batches in the durable
run journal, then tombstones generation-pinned `file_index_db` rows before
object deletion. Resume rechecks each candidate's provider ETag/version, size,
and current grace age while holding the batch fence, so a recreated key is
retained. A crash retries reconciliation idempotently. Completed runs delete
their batches, outcomes, and mark chunks while retaining only the small state
summary.

Before first use of this registry layout, stop older writers, upgrade every
writer, and run `crab gc --repair-registry --bucket <bucket>`. Destructive
bucket GC refuses incomplete coverage and does not read the retired aggregate
`.crab/ref-registry` object.

If any repository-scope object deletion or post-delete reconciliation fails,
Crab exits non-zero with `CRAB-E0322`. Its structured error details report the
number of successful deletions, failed deletions, and whether reconciliation
failed. Rerunning GC is safe because successful deletions are idempotent.

For conceptual background, see [Garbage Collection](/docs/cli/storage/garbage-collection).

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--dry-run` | `false` | Show what would be deleted without removing |
| `--scope` | `repo` | Collect repository objects, or use `bucket` for global deduplicated objects |
| `--bucket` | — | Physical bucket name required by bucket scope and registry maintenance |
| `--list-profile` | configured value | Override bucket listing with `adaptive`, `cost`, or `latency` |
| `--grace-period` | configured value (`24h` by default) | Don't delete objects newer than this |
| `--force` | `false` | Bypass age checks without bypassing registry or coordinator safety proof |
| `--yes` | `false` | Skip force-mode confirmation |
| `--resume <RUN_ID>` | — | Resume an interrupted destructive run |
| `--repair-closures` | `false` | Backfill and verify missing bucket shard closures |
| `--json` | `false` | Emit structured JSON output |
| `--jsonl` | `false` | Emit streaming structured output |

## Examples

### Preview garbage collection

```bash
crab gc --dry-run
```

### Run garbage collection

```bash
crab gc
```

### With shorter grace period

```bash
crab gc --grace-period 1h
```
