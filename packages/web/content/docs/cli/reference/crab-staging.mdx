# crab staging

Manage the staging area.

## Synopsis

```bash
crab staging stats
crab staging verify
crab staging clean [OPTIONS]
```

## Description

The Crab staging area (`.crab/staging/`) stores chunk data locally between
`crab add` and `git push`. The `crab staging` command provides subcommands
to inspect and clean this area.

For conceptual background, see [Staging Area](/docs/cli/storage/staging-area).

## Subcommands

### stats

Print staging area statistics (read-only, never blocks writers).

```bash
crab staging stats
```

### verify

Verify staged file metadata and chunk payloads before a push or after an
interrupted add:

```bash
crab staging verify
```

Verification is read-only. A failure means the local staged closure should not
be published until the affected paths are reset and added again.

### clean

Purge stale staging data.

```bash
crab staging clean
crab staging clean --force   # break stale locks from dead processes
```

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--force` | `false` | Force-break a stale lock held by a dead process |
| `--prune-abandoned` | `false` | Reclaim rolled-over segments left by a crashed or older add process |

`crab staging stats` also accepts `--json`; `crab staging clean` does not.

## Related commands

- [`crab add`](/docs/cli/reference/crab-add): write to the staging area.
- [`crab reset`](/docs/cli/reference/crab-reset): unstage files.
- [`crab du`](/docs/cli/reference/crab-du): inspect disk usage including staging.
