# crab workflow

Manage workflow-layer state for pipelines defined in `crab.yaml`.

## Synopsis

```bash
crab workflow [OPTIONS] <COMMAND>
```

## Commands

| Command | Purpose |
| --- | --- |
| `lockfile` | Manage `crab.lock` |
| `status` | Report per-stage state against `crab.lock` |
| `dag` | Render the workflow DAG as ASCII, Mermaid, DOT, or artifacts |
| `journal` | Inspect and prune workflow run journals under `.crab/workflow/runs/` |
| `push-cache` | Push local stage cache entries to the configured remote |

## Examples

### Inspect stage state

```bash
crab workflow status
```

### Render a DAG

```bash
crab workflow dag
crab workflow dag --format mermaid
```

### Inspect journals and publish cache entries

```bash
crab workflow journal ls
crab workflow push-cache --all
```

The administrative commands do not all share the same mutation boundary.
`status` and `dag` inspect declared state. `journal ls` and `journal show` read
run evidence, while `journal gc` removes older terminal journals. `push-cache`
uploads local stage-cache entries to the configured remote and therefore
requires network access and write authorization.

Start diagnosis with `status`, render `dag` when dependencies are unclear, and
inspect the relevant journal before pruning anything. Run each nested
`--help` because target selectors, formats, and retention controls belong to the
subcommand.
