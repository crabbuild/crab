## Findings considered and rejected or deferred

- Implement Git wire-protocol v2/stateless-connect in this plan: deferred.
  Crab's canonical serverless transport downloads immutable packs directly
  from object storage. The shipped `gix-transport` feature exposes an explicit
  scaffold, but the helper does not advertise it. Turning that scaffold into a
  second production fetch path needs a separate product and dependency-contract
  decision, not incidental wiring during correctness hardening. It is now
  covered by Plan 002.
- Implement `--filter=blob:none` immediately: rejected for this plan. Crab's
  current object-store layout publishes complete immutable Git packs and has no
  promisor-object/on-demand Git blob service. The safe near-term fix is to stop
  advertising or accepting a filter that is not applied, then design partial
  clone separately if measurements justify a second retrieval model.
  Plan 002 supplies that design and requires measured object-store savings.
- Add the RustFS smoke to Make or GitHub Actions: rejected because the existing
  add/push performance design explicitly keeps it manual. Deterministic
  in-memory and real-Git tests remain the PR gate.
- Change pointer, manifest, pack, xorb, shard, or bucket layouts: rejected.
  None of the verified integration gaps requires a durable-format migration.
- Add submodule and Git SHA-256 support: deferred to separate plans. Both are
  broader product capabilities and are not required to make the currently
  advertised SHA-1 remote-helper surface reliable.
