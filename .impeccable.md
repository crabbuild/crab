## Design Context

### Users
Crab is for developers, ML and data engineers, infrastructure teams, and technical decision makers who need to understand, evaluate, and operate large-file Git workflows without running dedicated LFS servers.

### Brand Personality
Technical, transparent, and practical. The interface should create confidence by explaining complex storage and Git internals with clear sequencing, concrete diagrams, and plain language.

### Aesthetic Direction
Use a restrained product-engineering style: crisp information hierarchy, readable technical diagrams, purposeful color, and dense but digestible layouts. Avoid marketing-heavy hero treatment on education pages, decorative visual noise, and generic dark neon "developer" styling.

### Design Principles
- Teach progressively: start with the mental model, then workflow, then internals, then operations.
- Make architecture visible: use diagrams, phase labels, and flow summaries for non-obvious systems behavior.
- Keep content scannable: expose level, prerequisites, concepts, and next steps before asking users to read deeply.
- Preserve trust: use balanced comparisons, concrete command flows, and practical operational framing.
- Respect working engineers: minimize fluff and make navigation goal-oriented.
