# crab install

Configure Crab at the machine level or per-repository.

## Synopsis

```bash
crab install [OPTIONS]
```

## Description

`crab install --global` is the recommended one-time setup command. After running it, any repository with a `.crab.toml` works immediately on clone — no per-repo `crab init` needed.

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--global` | `false` | Install machine-wide (filter driver in `~/.gitconfig`, shell completions) |
| `--aliases` | `false` | Install git aliases (`git ship`, `git crab-status`, `git crab-hydrate`) |
| `--no-completions` | `false` | Skip shell completion installation (useful for CI/headless environments) |
| `--log-level <level>` | — | Set log verbosity |

## Global Install

```bash
crab install --global
```

This performs:

1. **Filter driver registration** — adds `filter.crab.*` to `~/.gitconfig` so the filter activates in any repo with `.gitattributes` patterns
2. **Symlink verification** — checks that `git-remote-crab` is correctly symlinked and on PATH
3. **Credential discovery** — probes for cloud credentials and prints the result
4. **Shell completions** — installs tab-completion scripts for bash, zsh, and fish
5. **Success summary** — prints confirmation and next steps

After global install, the workflow for any Crab repo is:

```bash
git clone git@github.com:team/project.git  # has .crab.toml
cd project
# That's it — filter driver auto-configures from .crab.toml
```

## What Global Install Enables

The global filter driver checks for `.crab.toml` in the repo root when it activates. If found, it auto-configures the local `.crab/config.toml` from the project config. This means:

- No per-repo `crab init` needed after clone
- `.gitattributes` patterns are sufficient to trigger the filter
- Collaborators get a working setup just by cloning

For repos without `.crab.toml`, the filter passes through content unchanged — it's a no-op for non-Crab repos.

## Shell Completions

Completions are installed to standard locations:

| Shell | Path |
|-------|------|
| Bash | `~/.local/share/bash-completion/completions/crab` |
| Zsh | `~/.zfunc/_crab` |
| Fish | `~/.config/fish/completions/crab.fish` |

Use `--no-completions` to skip this step (e.g. in CI environments or Docker containers).

## Git Aliases

With `--aliases`, these git shortcuts are registered globally:

| Alias | Expands to | Description |
|-------|-----------|-------------|
| `git ship` | `crab ship` | Stage + commit + push |
| `git crab-status` | `crab status` | Show repo health |
| `git crab-hydrate` | `crab hydrate` | Materialize files |

```bash
crab install --global --aliases
```

Aliases are optional and off by default to avoid conflicts with existing git aliases.

## Per-Repository Install

Without `--global`, `crab install` configures only the current repository:

```bash
cd my-repo
crab install
```

This registers the filter driver in `.git/config` (local scope only). Useful when you can't or don't want to modify global git config.

## Idempotency

`crab install --global` is safe to run multiple times. It updates existing configuration rather than duplicating it.

## Uninstall

```bash
crab uninstall --global
```

Reverses all global changes:
- Removes `filter.crab.*` from `~/.gitconfig`
- Removes git aliases (if installed)
- Removes shell completion files
- Prints confirmation

## Examples

### Standard global setup

```bash
crab install --global
# ✓ Filter driver registered in ~/.gitconfig
# ✓ git-remote-crab symlink verified
# ✓ Credentials: AWS profile 'default' from ~/.aws/config
# ✓ Shell completions installed (bash, zsh, fish)
# ✓ Global setup complete. Any repo with .crab.toml will work automatically.
```

### Global setup with aliases

```bash
crab install --global --aliases
# ... (same as above, plus:)
# ✓ Git aliases installed: git ship, git crab-status, git crab-hydrate
```

### CI/headless setup

```bash
crab install --global --no-completions
```

### Per-repo only

```bash
cd my-project
crab install
```
