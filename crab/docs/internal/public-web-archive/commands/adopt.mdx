# crab adopt

Convert existing large files to Crab pointer blobs. Stages original content as deduplicated xorbs in your cloud bucket.

## Synopsis

```bash
crab adopt [OPTIONS]
```

## Description

`crab adopt` migrates large files that are already committed in your repository to Crab's chunked storage format. By default, it only affects the current working tree (HEAD-only mode) — no history rewriting, no force-push needed.

The command scans for matching files, chunks their content using CDC (content-defined chunking), stages the chunks, and replaces the files with pointer blobs. All changes are staged for commit but not committed automatically.

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--pattern <glob>` | — | File patterns to convert (repeatable). If omitted, uses `.crab.toml` `[track]` patterns or auto-detection |
| `--dry-run` | `false` | List files that would be converted without modifying anything |
| `--rewrite-history` | `false` | Rewrite all commits to replace matching files with pointers throughout history |
| `--force` | `false` | Required with `--rewrite-history` as a safety confirmation |
| `-j, --jobs <n>` | `8` | Number of parallel threads for chunking |
| `--json` | `false` | Output in JSON format |

## Pattern Resolution

When no `--pattern` flags are provided, `crab adopt` resolves patterns in this order:

1. `.crab.toml` `[track].patterns` — if the project config exists
2. Auto-detection — scans for files >1 MiB and well-known binary extensions

### Preview what would be adopted

```bash
crab adopt --dry-run
```

```

```

### Adopt with explicit patterns

```bash
crab adopt --pattern "*.safetensors" --pattern "*.bin"
```

### Adopt using project config patterns

```bash
# .crab.toml has [track] patterns = ["*.bin", "datasets/**"]
crab adopt
```

### Adopt with auto-detection

```bash
# No patterns specified, no .crab.toml — scans for large files
crab adopt
```

### Dry-run with JSON output

```bash
crab adopt --dry-run --json
```

### Parallel processing

```bash
crab adopt -j 16
```

### Full migration workflow

```bash
# 1. Initialize Crab
crab init crab://my-bucket/my-repo

# 2. Preview
crab adopt --dry-run

# 3. Adopt
crab adopt

# 4. Review and ship
git diff --cached --stat
crab ship -m "migrate large files to crab"
```

## HEAD-Only Mode (Default)

The default mode only modifies the current working tree and stages changes for the next commit. Historical commits retain original large blobs.

**Characteristics:**
- Safe — no history rewriting, no force-push
- Fast — only processes files in the current tree
- Non-disruptive — collaborators don't need to re-clone
- Reversible — `git checkout -- .` undoes changes before committing

**Limitation:** The `.git` directory retains historical large blobs. Future clones still download that history.

## History-Rewrite Mode

```bash
crab adopt --rewrite-history --force
```

Rewrites all commits to replace matching files with pointer blobs throughout history. This eliminates historical bloat entirely.

**Requirements:**
- `--force` flag is mandatory
- Working tree must be clean (no uncommitted changes)
- `git-filter-repo` must be installed

**After rewriting:**
```bash
git push --force-with-lease origin main
```

**Warning:** This rewrites shared history. All collaborators must re-clone or reset after you force-push.

## What It Does (HEAD-Only)

1. Resolves file patterns (flags → `.crab.toml` → auto-detect)
2. Walks the working tree for matching files
3. For each file: reads content → CDC chunks → stages to local staging area
4. Replaces file content with a pointer blob (~128 bytes)
5. Updates `.gitattributes` with tracking patterns
6. Runs `git add` on all modified files + `.gitattributes` + `.crab.toml`
7. Prints summary and next-step hint
