# crab ship

One-command add + commit + push.

## Synopsis

```bash
crab ship [OPTIONS] [PATTERNS...]
```

## Description

`crab ship` combines three operations into one:

1. **Stage** — runs `crab add` on the specified patterns (CDC chunking + dedup)
2. **Commit** — creates a git commit with the provided message
3. **Push** — pushes to the remote (uploads xorbs + updates manifest)

This is the daily-driver command for getting changes into your repository.

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `-m, --message <msg>` | — | Commit message (required unless `--dry-run`) |
| `--dry-run` | `false` | Show what would be staged, committed, and pushed without doing it |
| `--log-level <level>` | — | Set log verbosity |

## Arguments

| Argument | Default | Description |
|----------|---------|-------------|
| `PATTERNS` | `.` (all files) | File patterns to stage. If omitted, stages everything in the working tree |

## Default Patterns

When no patterns are specified, `crab ship` defaults to `.` — staging all tracked files in the working tree. This matches the common `git add .` muscle memory.

```bash
# These are equivalent:
crab ship -m "update"
crab ship -m "update" .
```

## Auto-Manifest Creation

On the first push to a new remote (when no manifest exists yet), `crab ship` automatically creates the initial manifest. No separate setup step needed.

## Auto-Include `.crab.toml` and `.gitattributes`

If `.crab.toml` or `.gitattributes` were modified during the add step (e.g. new tracking patterns detected), they're automatically included in the commit.

## Dry-Run

```bash
crab ship --dry-run
```

Shows:
- Files that would be staged (with sizes)
- The commit that would be created
- The push target

No files are modified, no commit is created, no data is uploaded.

## Examples

### Ship all changes

```bash
crab ship -m "add training data"
```

### Ship specific patterns

```bash
crab ship -m "update models" "models/**"
```

### Preview before shipping

```bash
crab ship --dry-run
```

Output:
```
Dry run — no changes will be made.

Would stage:
  models/bert.safetensors  (1.3 GB, 847 chunks)
  datasets/train.parquet   (540 MB, 312 chunks)

Would commit:
  "update training pipeline"
  2 files changed

Would push to:
  crab://ml-team/my-model (remote: origin)
```

### First commit in a new repo

```bash
crab init crab://my-bucket/my-repo
# ... add some files ...
crab ship -m "initial commit"
```

The first ship creates the remote manifest automatically.

### Daily workflow

```bash
# Make changes
vim train.py
python train.py  # produces model.bin

# Ship everything
crab ship -m "improve accuracy to 94%"
```

## What Happens Internally

1. `crab add <patterns>` — scans matching files, CDC-chunks new/modified content, stages chunks to local staging area, replaces files with pointer blobs in the index
2. `git add .crab.toml .gitattributes` — if modified, include config files
3. `git commit -m <message>` — creates the commit
4. `crab push` — uploads staged xorbs to cloud storage, updates the manifest

If the remote manifest doesn't exist (first push), it's created before uploading.

## Error Cases

| Scenario | Behavior |
|----------|----------|
| No credentials configured | Fails with clear message before attempting upload |
| Remote unreachable | Fails after commit (commit is local, push can be retried) |
| No changes to stage | Prints "nothing to ship" and exits |
| No commit message | Prints usage hint and exits |
